# Dunhill商品正价价格更新

自动从品牌方价格变动文件同步商品价格到数据库。

---

## 【核心原则】同一SPU的日期必须连续

**这是本工具最重要的规则，必须严格遵守！**

同一个 SPU 可能有多条调价记录（不同时间段不同价格），这些记录的日期范围必须**紧密衔接**：

- **连续**：下一条的 `validFrom` = 上一条的 `validTo` + 1天
- **不能重叠**：时间段不能有交集
- **不能有间隙**：时间段之间不能有空档

### 正确示例

```
记录1: 2024-01-01 ~ 2024-06-30
记录2: 2024-07-01 ~ 2024-12-31  ✓ 连续（6/30 + 1 = 7/1）
```

### 错误示例 - 重叠

```
记录1: 2024-01-01 ~ 2024-07-15
记录2: 2024-07-01 ~ 2024-12-31  ✗ 重叠（7/15 >= 7/1）
```

### 错误示例 - 间隙

```
记录1: 2024-01-01 ~ 2024-06-30
记录2: 2024-08-01 ~ 2024-12-31  ✗ 间隙（缺少7/1~7/31）
```

**脚本会在执行前自动验证此规则，发现问题会停止执行并报告错误。**

## 【安全原则】删除操作必须交互确认

**所有数据库 DELETE 操作在执行前必须：**

1. 列出完整的待删除记录清单（SPU、时间段、RSP、名称）
2. 通过交互式确认获得用户明确同意
3. 只有用户确认后才执行

**绝对不能跳过确认直接删除。**

## 快速开始

### 推荐工作流程

**Step 1: 预览新增记录（人工验证）**

在执行价格更新前，先运行预览脚本查看有哪些新增记录：

```bash
python scripts/preview_new_records.py
```

这会在价格文件目录下生成 `new_records_preview.csv`，可以人工审核是否需要导入。

**Step 2: 执行价格更新**

确认新增记录需要导入后，执行更新：

```bash
# 预览模式（不实际更新）
/dunhill-price-updater --dry-run

# 实际更新
/dunhill-price-updater
```

### 命令参数

| 参数                  | 说明                                       |
| --------------------- | ------------------------------------------ |
| `--dry-run`         | 预览模式，只显示变更不执行实际更新         |
| `--skip-overlap`    | 跳过日期重叠检查（确认重叠是预期的）       |
| `--skip-continuity` | 跳过日期连续性检查（**不推荐使用**） |
| `--config`          | 指定配置文件路径                           |

## 核心设计原则

### 1. 复合唯一键匹配

使用 `(spu, validFrom, validTo)` 作为复合唯一键：

- 同一SPU在不同时间段可以有多条调价记录
- 判断记录是否存在基于这三个字段的组合
- **不会删除**数据库中已有但Excel中没有的记录

### 2. 空值处理 (validTo)

Excel中 `validTo` 为空/NaT 时，自动转换为 `9999-12-31`：

- 表示该价格长期有效
- 避免插入NULL值导致的数据问题

### 3. 日期类型转换

正确处理 Python datetime 到 MySQL date 的转换：

- Excel中的日期已经是 datetime 类型
- 插入前转换为 Python date 对象
- 避免类型不匹配导致的插入失败

### 4. 日期重叠检查

新增记录时会检查是否与现有记录存在日期重叠：

- 重叠定义：两个时间段 `[from1, to1]` 和 `[from2, to2]` 有交集
- 发现重叠时会警告并停止执行
- 可使用 `--skip-overlap` 跳过检查

## 工作流程

### Step 1: 定位最新价格文件

- 扫描目录: `${DUNHILL_DATA_DIR}/product/调价清单/`
- 文件模式: `PRICE_YYYYMMDD.xlsx`
- 自动选择修改时间最新的文件

### Step 2: 读取并筛选数据

**Excel文件结构:**

- Row 0: "Pricing Conditions" 标题行
- Row 1: 空行
- Row 2: 列名 (spu, Product - Name, CON - Valid From, ...)
- Row 3+: 数据

**筛选条件:**

1. **只要SPU记录**: 商品名称(Product - Name)中不包含颜色和尺码信息
   - SPU例: `COLLEGE PENNY LOAFER LTR`
   - SKU例: `COLLEGE PENNY LOAFER LTR, BLACK, 39, .0` (排除)
   - **注意**: 仅靠名称逗号过滤不够，部分SKU名称无逗号但编码是长编码（如 `DU24R3116GN001R`）
2. **排除SKU编码（前缀检查）**: 对编码长度 > 13 的记录，检查是否存在长度 8-13 的前缀编码在同一文件中。有前缀 = SKU，排除
   - 例: `DU24R3116GN001R`(len=15) 有前缀 `DU24R3116GN`(len=11) → 排除
   - **例外**: PIPES 和 SMOKERS 类目不做前缀检查（见下方规则）
3. **PIPES 和 SMOKERS 类目**: SPU = SKC = SKU，编码不区分层级
   - 即使编码存在前缀关系，每个编码都是独立 SPU，不做前缀排除
   - PIPES: `DUDPZ*` 前缀
   - SMOKERS: `DUHS*`, `DUSF*`, `DUPA*` 前缀
4. **排除非标准SPU编码**:
   - SPU编码以`_`结尾的记录（非标准编码）
   - 已知的SKC颜色编码（对应SPU已在数据库中）
5. **零售价不为空**: ZRSP字段有值且大于0

**已排除的SKC编码列表:**

以下6个SKC编码会被自动过滤（对应SPU已在数据库中）：
- `DU1AB575211`, `DU1AB575216`, `DU1AB575221` (对应SPU: DU1AB5752)
- `DU1DBFB5211`, `DU1DBFB5216`, `DU1DBFB5221` (对应SPU: DU1DBFB52)

**字段映射:**

| Excel源文件字段   | 数据库字段 | 用途                               |
| ----------------- | ---------- | ---------------------------------- |
| ART - Hier. Lvl 5 | category   | 商品类目                           |
| spu               | spu        | 商品SPU编码                        |
| Product - Name    | name       | 商品名称                           |
| CON - Valid From  | validFrom  | 价格生效日期                       |
| CON - Valid To    | validTo    | 价格失效日期（空值转为9999-12-31） |
| ZRSP              | rsp        | 零售价格                           |

### Step 3: 对比数据库现有记录

连接数据库并获取 `dunhill_价格源` 表中的现有记录：

- 使用复合键 `(spu, validFrom, validTo)` 进行匹配
- 检查新增记录是否会导致日期重叠

### Step 4: 执行更新/新增操作

- **已存在记录（价格变化）**: 更新 ValidFrom, ValidTo, rsp, category, name等字段
- **新记录（无重叠）**: 插入到表中
- **新记录（有重叠）**: 警告并停止

## 改进计划

### 自动从 SKC/SKU 记录推断 SPU 价格

**背景**：Excel 源文件可能缺少 SPU 级别的调价记录，但存在对应的 SKC（颜色编码）或 SKU 记录。

**编码规则**：

- SPU（短编码）：`DU1DBFB52`
- SKC/SKU（长编码）：`DU1DBFB5211`、`DU1DBFB5216`（在 SPU 基础上增加后缀）

**原理**：同一商品的 SKC/SKU 调价记录与 SPU 调价记录应该是一致的（相同时间段、相同价格）。

**改进方向**：当 Excel 缺少 SPU 记录但存在对应 SKC/SKU 记录时，自动用 SKC/SKU 的价格更新 SPU。

```
示例：
  数据库 SPU: DU1DBFB52 | RSP: ¥6,750
  Excel SKC: DU1DBFB5211 | RSP: ¥7,250 (最新价格)

  自动推断：用 SKC 的 ¥7,250 更新 SPU 记录
```
