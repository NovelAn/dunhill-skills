# Dunhill Daily Report Automation

Automated workflow for generating Dunhill daily reports from Taobao e-commerce data.

## ⚠️ CRITICAL EXECUTION REQUIREMENTS

**MUST EXECUTE STEPS SEQUENTIALLY WITH STRICT DEPENDENCY CHECKING:**

1. **Step 2 MUST complete successfully BEFORE Steps 3, 4, or 5**
   - Step 2 runs `run.py` which downloads all data sources and uploads them to the database
   - You MUST wait for Step 2 to return exit code 0 (success) before proceeding
   - Do NOT start Steps 3 or 4 until Step 2 shows: `[OK] 步骤2执行成功！可以继续执行后续步骤。`
   - Steps 3 and 4 depend on this data being completely loaded into the database
   - If Steps 3 or 4 run before Step 2 completes, the Excel refresh will fail or show incomplete data

2. **Mac execution boundary**
   - On macOS, this skill can reliably run Step 1 and Step 2 only.
   - Steps 3 and 4 require Windows Excel with Power Query / MySQL data connection support.
   - Step 5 depends on screenshots/files generated by Steps 3 and 4, so it is also Windows/Excel-environment dependent.
   - Do not promise full Step 3-5 automation on Mac. Use a Windows machine, remote Windows host, or manual report-refresh workflow for those steps.

3. **Execution Order (ENFORCED):**
   ```
   Step 1 (optional) → Step 2 → Step 3 → Step 4 → Step 5
                         ↑
                    MUST WAIT HERE
                    Until run.py exits
                    with code 0
   ```

4. **How to Verify Step 2 Completion:**
   - Look for: `[OK] 步骤2执行成功！可以继续执行后续步骤。`
   - Check exit code is 0 (not 1)
   - Verify all tasks show as completed in summary
   - Only then proceed to Step 3

5. **If Step 2 Fails:**
   - DO NOT proceed to Steps 3, 4, or 5
   - Report the failure to the user
   - Show the error messages from Step 2
   - Ask user if they want to retry Step 2

## Workflow Steps

Execute all steps sequentially for complete daily report generation, or run individual steps for testing.

### Step 1: Collect Data from Web Platforms

Automates data collection from Taobao platforms:
- Export refund list as Excel
- Download live streaming core indicators
- Download transaction order details (payment & confirmation time)
- Supplement complete QuickBI TM order/refund files when preview rows exceed 50

#### Step 1 Routing Rule

All model runtimes use the same Playwright Chrome Extension + MCP bridge path:

```bash
python -u scripts/step1_collect_data.py
```

- The wrapper runs `scripts/step1_chrome_bridge.py`.
- Refund export uses `scripts/export_refund_chrome.py`.
- Live export uses `scripts/export_live.py`.
- QuickBI complete-file supplement uses `scripts/export_quickbi_chrome.py`.
- The scripts connect to local Chrome through Playwright MCP Extension, reuse the user's logged-in Chrome profile, and run high-speed page actions.
- Before running, set the token from the Chrome extension status page:
  ```bash
  export PLAYWRIGHT_MCP_EXTENSION_TOKEN="..."
  ```
- If the token is not set, Chrome may show a Playwright Extension connection confirmation page.
- Do not use Codex Extension / browser-use computer-use clicks for Step 1; QianNiu/Taobao pages are too slow and unstable through that route.
- `scripts/step1_collect_data_cdp.py` is kept only as a legacy fallback.

#### Step 1a: 千牛退款列表导出

**Bridge path**:
```bash
python -u scripts/export_refund_chrome.py
```

`scripts/export_refund.py` has been removed. Do not use an independent Playwright persistent profile for the main refund export. `scripts/step1_collect_data_cdp.py` is the only legacy fallback.

**备用方式** (Playwright MCP 手动操作 SOP):

> **IMPORTANT**: 千牛新版 UI 使用 Next.js (`next-select` 组件)，不是原生 HTML `<select>`。旧版独立 Playwright profile 脚本中的 CSS selector / text-based 选择器策略对新版 UI 无效。以下 SOP 仅在 MCP bridge 脚本失效、页面结构变化时需要手动操作时使用。

**目标 URL**: `https://myseller.taobao.com/home.htm/trade-platform/refund-list`

**操作流程（严格按顺序）**:

1. **筛选售后状态为"全部"** — 最关键步骤，默认只显示"进行中的订单"
   - 在"组合查询"区域找到"售后状态"下拉框（`next-select-multiple` 组件，显示"已选择 1/14 项 进行中的订单"）
   - 点击触发 `next-select-trigger` 打开下拉菜单
   - 先取消"进行中的订单"（点击该选项取消勾选），再点击"全部"选中
   - 关闭下拉菜单后，确认显示变为"已选择 1/14 项 全部"

2. **点击"搜索售后单"** — 必须点击此按钮才能应用筛选
   - 验证数据量变化：从 ~120 条变为 ~1200 条（取决于时间范围）
   - 页面显示"已选 (0/N)"，N 应为全部退款单数

3. **点击"批量导出"** — 打开导出设置对话框
   - 确认所有字段分类的"全选"已勾选（默认全部选中）
   - 点击"生成报表"

4. **确认隐私弹窗** — 点击"确认"

5. **下载报表**
   - 点击"查看已生成报表" → 再次确认隐私弹窗 → **自动打开新标签页**
   - 新标签页 URL: `https://myseller.taobao.com/home.htm/trade-platform/refund-list/export-list`
   - 如 Playwright MCP 未自动切换标签页，直接 navigate 到此 URL
   - 找到最新一条（按"报表申请时间"降序排列，第一条即为最新）
   - 验证：确认"进度"为"已完成"，"预计退款单数量"与步骤2的数据量一致
   - 点击"下载退款单报表"

6. **验证下载**
   - 文件下载到 `~/Downloads/`，文件名为数字 ID（如 `2208771659256_1779644001049_456.xlsx`）
   - 按修改时间排序取最新文件：`ls -lt ~/Downloads/*.xlsx | head -1`
   - 用 openpyxl 验证行数匹配

**关键注意事项**:
- "售后状态"中的"全部"是 14 个选项之一，不是"全选"元操作。选中"全部"即表示不按状态筛选
- 5 分钟内只能导出一次（"生成报表"按钮显示倒计时限制）
- 导出是异步的，报表生成后需到 export-list 页面下载；不会在当前页面自动弹出下载
- 下载文件名是系统生成的数字 ID，需事后重命名为业务可读名称
- Playwright MCP 的 ref 会随页面变化失效，优先用 `browser_evaluate` + JavaScript 操作 DOM

#### Step 1b: 直播数据源导出

**Bridge path**:
```bash
python -u scripts/export_live.py
```

`export_live.py` 默认通过 Playwright MCP Extension 连接本机 Chrome，而不是启动新的 Playwright profile。这样能复用 Chrome 已登录状态，避免每次打开新实例后扫码登录。

**准备要求**:
- Chrome 已安装 Playwright Extension。
- Chrome 中已登录淘宝/淘宝直播平台。
- 推荐设置 `PLAYWRIGHT_MCP_EXTENSION_TOKEN`，用于跳过扩展连接确认弹窗。
- 如果触发滑块，脚本会等待用户在 Chrome 中手动完成验证。

**页面 URL**:
- 概览页: `https://liveplatform.taobao.com/restful/index/live/overview?forceShowLegacyVersion=true`
- 场次分析: `https://liveplatform.taobao.com/restful/index/data/live`
- 交易明细: `https://liveplatform.taobao.com/restful/index/data/transaction?page=OrderDetail`

**操作流程**:

1. **直播间大盘数据** — 概览页"数据概览" tab
   - 找到并点击"下载"按钮
   - 等待下载完成

2. **直播分场次效果** — 概览页"分场次效果" tab（如存在）
   - 找到并点击"下载"按钮
   - 等待下载完成

3. **直播间成交订单明细** — 交易明细页
   - 第一次下载：选择时间类型为"支付时间"，点击"查询"后下载
   - 第二次下载：选择时间类型为"确认收货时间"，点击"查询"后下载

**下载文件命名规则**:
- 大盘数据: `直播间大盘数据-YYYY-MM-DD.xlsx`
- 分场次效果: `直播分场次效果-*.xlsx`
- 订单明细: `直播间成交订单明细-*.xlsx`

#### Step 1c: QuickBI 天猫三源完整文件补充

**Bridge path**:
```bash
python -u scripts/export_quickbi_chrome.py --sources all
```

`scripts/step1_collect_data.py` 默认会在退款和直播下载后运行该补充脚本。仅调试退款/直播时可使用：
```bash
python -u scripts/step1_collect_data.py --skip-quickbi
```

**覆盖的数据源**:
- `BI_tm_t01_trade_order_line`（天猫 t01 订单源）
- `BI_tm_trade_refund_info_allsuc_filter`（天猫退款成功退款源）
- `BI_tm_trade_refund_info_paydate_filter`（天猫待退款中退款源）

**运行规则**:
1. 打开 QuickBI 页面并读取底部 `查询结果共XX条`。
2. 如果 `XX <= 50`，跳过；Step 2 的网页爬虫可完整获取。
3. 如果 `XX > 50`，打开右侧任务列表并创建本轮 `纯数据 Excel` 取数任务。
4. 记录本轮任务开始时间，等待后台任务完成。
5. 刷新页面并打开右侧任务列表，只点击 `创建于` 晚于本轮开始时间、且显示绿色成功图标和下载图标的最新任务。
6. 下载文件落到 `~/Downloads`，文件名形如 `BI_tm_t01_trade_order_line_自助取数_YYYYMMDD_HH_MM_SS.xlsx`。

**与 Step 2 的关系**:
- Step 2 仍会抓取这三个 QuickBI 源，重复下载没有关系。
- 数据库导入使用 `INSERT IGNORE`，重复行不会重复插入。
- Step 1c 的目的只是确保当天 `~/Downloads` 中有完整 QuickBI 文件，避免 Step 2 预览爬虫最多 50 行导致数据不完整。

### Step 2: Run Data Import Scripts ⚠️ CRITICAL STEP

**PREREQUISITE**: None
**CRITICAL**: This step MUST complete successfully before Steps 3, 4, or 5 can execute.

Executes internal data import Python scripts:
- **Cookie health check**: Pre-checks `.taobao.com` cookies before launching `run.py`. If expired, Step 2 first runs `/Users/novel/projects/data-import/scripts/login/taobao_login_mcp.py` to sync the latest QianNiu/Taobao cookies from normal Chrome through Playwright MCP Extension. This reuses the Chrome login state created by Step 1 and refreshes only the high-frequency Taobao/QianNiu authentication while preserving low-frequency QuickBI/SYCM/JYCM cookies. If MCP cookie sync fails, Step 2 falls back to the legacy interactive login script and auto-selects option `1` (千牛/淘宝).
- Runs `${ETL_PIPELINES_DIR}/run.py`
- Downloads all data sources (QuickBI, SYCM, JYCM, etc.)
- Uploads all data to database
- Runs the daily Alimama crawler and writes paid media data to the database
- Runs stored procedure `UpdateMaskedBuyerNicknames` to auto-decrypt historical buyer nicknames via SQL (reduces crawler request volume and avoids Alibaba anti-bot warnings)
- Runs order crawlers (nick + fq) for remaining undecrypted orders
- Runs buyer type updates (PFS + DTC)
- Monitors output for QuickBI table warnings (>50 rows)
- Step 1 already performs QuickBI complete-file supplement for the three TM sources; Step 2 may still warn for QuickBI preview tables and can prompt for manual download if other QuickBI files are missing
- Re-runs upload script if manual downloads occurred

**Script**: `scripts/step2_run_import.py`

**SUCCESS INDICATORS**:
- Exit code: 0
- Message: `[OK] 步骤2执行成功！可以继续执行后续步骤。`
- All data sources uploaded to database

**DO NOT PROCEED TO STEP 3 UNTIL**:
- Step 2 script has exited (process terminated)
- Exit code is 0 (success)
- Success message is displayed

**When QuickBI exceeds 50 rows**: Step 1 should already have downloaded complete files for the three TM QuickBI sources. If Step 2 still reports missing QuickBI files, follow its prompt or rerun `python -u scripts/export_quickbi_chrome.py --sources all`.

**Alimama auth**: 阿里妈妈 `csrfId`/cookies 通常只有约 1 天有效期。日常执行 Step 2 时推荐使用：
```bash
python -u scripts/step2_run_import.py --refresh-alimama-auth-first
```
This refreshes Alimama auth through the Playwright MCP Extension and local Chrome before running the Alimama crawler. If omitted, the crawler will still auto-refresh once when it detects CSRF failure. Use `--skip-alimama` only for emergency debugging when the Alimama platform is unavailable.

### Step 3: Generate PFS Report ⚠️ DEPENDS ON STEP 2

**PREREQUISITE**: Step 2 MUST complete successfully first
**DEPENDENCY**: Requires all data from Step 2 to be loaded into database
**RUNTIME LIMITATION**: Requires Windows Excel with Power Query / MySQL connection support. Mac Excel cannot refresh these database-backed Power Query reports.

Automates PFS Excel report generation:
- Opens `dunhill pfs daily report.xlsx`
- Refreshes all data connections (2-3 minutes)
- Copies "Daily" sheet as values to new workbook
- Saves snapshot to snapfile directory
- Takes screenshots of key ranges (B8:A37, Daily Highlights if data exists)
- Saves JPEGs with yesterday's date (YYYY-MM-DD format)

**Script**: `scripts/step3_pfs_report.py`

**Output**:
- `daily_report_snapfile/dunhill pfs daily report_YYYY-MM-DD.xlsx`
- `daily_report_snapshot/dunhill pfs daily report_YYYY-MM-DD.jpeg`
- `daily_report_snapshot/pfs_daily_highlights_YYYY-MM-DD.jpeg` (if data exists)

### Step 4: Generate DTC Report ⚠️ DEPENDS ON STEPS 2 & 3

**PREREQUISITE**: Steps 2 AND 3 MUST complete successfully first
**DEPENDENCY**: Requires all data from Step 2, and MUST wait for Step 3 to complete
**EXECUTION ORDER**: Step 3 → Step 4 (SEQUENTIAL, NOT PARALLEL)
**RUNTIME LIMITATION**: Requires Windows Excel with Power Query / MySQL connection support. Mac Excel cannot refresh these database-backed Power Query reports.

Automates DTC Excel report generation:
- Opens `dunhill OFS&WBTQ daily sales report.xlsx`
- Refreshes all data connections (2-3 minutes)
- Copies "Daily Sales Trend" sheet as values
- Saves snapshot to snapfile directory
- Takes screenshot of "Daily" sheet (A4:T49)
- Saves JPEG with yesterday's date

**Script**: `scripts/step4_dtc_report.py`

**Output**:
- `daily_report_snapfile/dunhill OFS&WBTQ daily sales report_YYYY-MM-DD.xlsx`
- `daily_report_snapshot/dunhill OFS&WBTQ daily sales report_YYYY-MM-DD.jpeg`

### Step 5: Create Email Drafts ⚠️ DEPENDS ON STEPS 3 & 4

**PREREQUISITE**: Steps 3 and 4 MUST complete successfully first
**DEPENDENCY**: Requires screenshot files from Steps 3 and 4
**RUNTIME LIMITATION**: On Mac, Step 5 can only be run after the Step 3/4 screenshots and snapshot workbooks have already been generated elsewhere.

Creates Outlook email drafts with report attachments:
- Reads email template `.msg` files (if provided in `assets/email_templates/`)
- Replaces `{date}` placeholder with yesterday's date (YYYY-MM-DD)
- Attaches screenshot files
- Saves to Outlook drafts folder (does NOT send)

**Script**: `scripts/step5_email_drafts.py`

**Note**: Emails are saved as drafts for manual review before sending.

**If no templates provided**: Creates basic email drafts with standard format.

### Mac Daily Orchestrator (Step 1-2)

Use the orchestrator for scheduled Mac runs:

```bash
# Actual daily execution in the macOS GUI login session

# Read-only status command for Codex Automation
python -u scripts/report_daily_status.py
```

Do not run `daily_orchestrator.py` from a scheduled Codex sandbox. The user
LaunchAgent owns Step 1-2 execution; Codex Automation only reads and reports the
result.

Default behavior:
- Runs Step 1 then Step 2.
- Step 2 refreshes Alimama auth first by default.
- On macOS, the orchestrator wraps itself with `caffeinate -dimsu` so the Mac stays awake while the run is active.
- Writes state and logs to `runs/YYYY-MM-DD/`.
- After Step 1 and Step 2 both succeed, sends a concise business-facing Feishu/Lark group notification to `数据更新提醒`, mentioning 徐加琪 and 唐玉霞.

Useful options:
```bash
python -u scripts/daily_orchestrator.py --from step2

python -u scripts/daily_orchestrator.py --dry-run
```

## Common Issues

**Excel doesn't close**: `taskkill /F /IM Excel.exe`

**Login fails**: See [Setup Guide - Login Solutions](references/setup.md#login-solutions)

**Session expired**: Re-login in normal Chrome with Taobao mobile app, then rerun the Playwright MCP Extension bridge.

**Cookie health check failed (cookies 已过期)**: Step 2 会自动检测 `.taobao.com` cookies 有效性，约每 2-3 天过期一次。默认先运行 `/Users/novel/projects/data-import/scripts/login/taobao_login_mcp.py`，通过 Playwright MCP Extension 从本机 Chrome 同步最新千牛/淘宝 cookies；这通常能直接复用 Step 1 的登录态，无需扫码。只有 MCP 同步失败时才回退到旧的交互式 `taobao_login.py`。若要关闭自动登录，可运行 `python -u scripts/step2_run_import.py --no-auto-login`。

**Steps 3-5 on Mac**: Mac 版 Excel 不支持此 skill 依赖的 Power Query / MySQL 数据连接刷新。Mac 本机只承诺 Step 1-2；Step 3-4 请在 Windows Excel 环境执行，Step 5 依赖 Step 3-4 生成的截图和快照文件。

**Nick/fq 爬虫大量失败**: 可能是 cookies 过期，也可能是请求量过大触发风控。系统已通过 `UpdateMaskedBuyerNicknames` 存储过程预先解密历史老客昵称以减少爬虫请求量。

**QuickBI exceeds 50 rows**: Step 1 runs `scripts/export_quickbi_chrome.py` to create and download complete QuickBI files for the three TM sources when preview rows exceed 50.

**Download button not found**: Script will pause and prompt for manual operation

For complete troubleshooting guide, see [Troubleshooting](references/troubleshooting.md).
